# turboblake, the library

The official [`blake3`](https://crates.io/crates/blake3) crate (1.8.7), with
one change: when an update reaches a big subtree, it is hashed on every core
by a [Bend2](https://bend-lang.com) engine instead of on one. Same API, same
library name (`blake3`), same output; upstream's own test suite passes with
the engine taking every subtree. It is the library of the `turboblake`
crate, which also carries the command line (`bend/crate`, generated by
`gen.sh` here); `default-features = false, features = ["std"]` leaves the
command line's dependencies out.

```toml
[dependencies]
turboblake = { git = "https://github.com/gunta/turboblake" }
```

From the next crates.io release it is `turboblake = "1.8"`; turboblake
1.8.7 on crates.io is the command line alone. Your code keeps `use blake3::…`. `blake3::hash` and `Hasher::update` go
through the engine past a size it calibrates at the first big input (about
256 KiB on an Apple M5 Pro), in every mode (keyed hashing and key derivation
too). `update_rayon` hands it only what it beats rayon on: input it reads in
place, in the default mode, up to 16 MiB (1.3-2x faster there); the rest is
upstream's rayon. Below that, and in `no_std` builds, it is upstream's code.
On macOS the library reserves its heap's room when it loads, so the buffers
your program allocates afterwards are read in place.

To swap it in for every crate in a dependency graph (iroh, for example),
generate a copy named `blake3` and patch it in:

```bash
git clone https://github.com/gunta/turboblake && TURBOBLAKE_NAME=blake3 turboblake/bend/rust/gen.sh vendor/blake3
```

```toml
[patch.crates-io]
blake3 = { path = "vendor/blake3" }
```

Building needs clang (the engine is the C that Bend2 emits); without it, the
crate builds as upstream's and says so in a warning. `TURBOBLAKE=0` turns
the engine off at run time, `TURBOBLAKE_THREADS=<n>` caps its threads,
`TURBOBLAKE_TRACE=1` prints what it did.

On a GPU (ADR 0017), loaded at run time (Metal on macOS, CUDA through
libcuda elsewhere; nothing changes without one):

```rust
let mut h = blake3::Hasher::new();
unsafe { h.update_cuda(tensor_ptr, len, std::ptr::null_mut()) };   // CUDA device memory
unsafe { h.update_metal(mtl_buffer, offset, len) };                 // an id<MTLBuffer>
let mut m = blake3::gpu::Memory::new(1 << 30).unwrap();              // memory the GPU reads
blake3::hash(&m);                                                   // split between CPU and GPU
```

`blake3::gpu::backend()` says which one runs; `TURBOBLAKE_GPU=0` turns it
off, `TURBOBLAKE_NO_GPU=1` builds without it.

How it works, and the benchmarks:
[github.com/gunta/turboblake](https://github.com/gunta/turboblake) (see
`bend/lib/README.md`).
