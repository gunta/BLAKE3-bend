# ADR 0010: More laws: outboards, counts, the streaming stack

Date: 2026-10-26
Status: accepted

## Context

ADR 0007 left 20 laws: known answers, the 8-lane path for every input, and
two tree theorems (segments, levels). Two paths written since had no law at
all, and both run on the headline benchmarks:

- **iroh outboards** (ADR 0008): `tree8o` is `tree8` that also keeps the
  pairs above each 16-chunk group. No known answer runs it, and they stop
  at 8 KiB anyway (the checker computes ~1.5 compressions a second), while
  most of tree8o's own code (`leaf32o`, outboard nodes) runs only past
  16 KiB. A slip there (a swapped parent, a lost ROOT flag) had only
  `ob_check` against bao-tree to catch it.
- **The streaming stack** (ADR 0009): `b3io.bend` merges a streamed file's
  segment CVs as BLAKE3's Hasher merges chunks, lazily, on a stack. It
  hashed the 101.5 GB shard; it was checked only by that digest and
  `test/big.py`.

The goal is to show what Bend's checker gives that the Rust crate cannot:
claims about every input, not tests on chosen ones.

## Decision

Eight more laws, all generated by `tools/gen_laws.py` like the others:

| law | what it says | proof |
|-----|--------------|-------|
| `consts.iv`, `consts.flags` | the IV and the four flags are `c/blake3_impl.h`'s (read by the generator) | `{==}` |
| `ob.hash` | for **every** array and length, the outboard tree's CV is `hash`'s | `ob.go` |
| `ob.at` | the same for every span (b3sum's 1 GiB segments) | `ob.go` |
| `tree.leaves` | for all k and r < 2^k, BLAKE3's tree over chunks 0..r has r + 1 leaves | `levels.root`, and pairing keeps the leaf total |
| `tree.parents` | ... and r parents: n chunks cost n - 1 parent compressions; g groups give g - 1 outboard pairs | a tree has one parent fewer than leaves |
| `stream.shape` | for every r < 2^fuel, b3io's stack over r + 1 segments builds BLAKE3's tree | a binary increment, below |
| `stream.order` | for every r and fuel, its leaves are segments 0..r, in order | merges join neighbours, below |

### Outboards: an induction over the code that runs

`tree8o.eta` proves `tree8o(...) == (tree8(...), snd(tree8o(...)))` for
every argument, by induction on the depth; `ob.go` takes the first
component. Two constraints set its form:

- **Arrays are affine.** A first try stated `fst(tree8o) == tree8` and
  needed, at a Split node, both the induction hypothesis and a lemma about
  `join.o` on the same subtree: two uses of the subtree's array, which the
  checker refuses. The pair equation rewrites each subtree once (`%IH : P`,
  the motive is dead, so its uses are free) and leaves `join.pick` on
  plain CVs, closed by `pick.eta` with its CVs erased.
- **Pairs have no eta**, and a `match` cannot scrutinize a computed value.
  `fin.eta` opens the 32-chunk leaf's result (an array and a CV8) inside a
  lemma of its own.

The proof never reads the array: both trees make the same reads, node for
node, and the checker compares the stuck terms. Mutating `blake3.bend`
(the children of `join.pick`'s parent swapped, or its ROOT flag dropped)
fails the gate.

### Streaming: the lazy merge as a binary increment

The model is b3io's `stk.pop2`, `stk.even`, `stk.lazy`, `stk.fin`,
`stk.root` and `stream.go`, def for def, with a `Tree` (`Seg{k}`,
`Par{l, r}`) for a CV and a Nat for the U32 count. After segments 0..v the
stack is a leaf over `bits(f, 0, v)`: the complete trees of v's 1 digits,
lowest on top. Then:

- `lazy.inc`: the merges before segment v + 1 carry v's trailing 1s, like
  a binary increment. Case split on v's parity with the equation
  `odd(v) == b` (matching w refines it), with `par.even`, `half.even`,
  `par.odd`, `half.odd`.
- `bits` keeps an overflow as a pile of complete trees (`List.replicate`
  at depth 0), so `lazy.inc` holds with no bound and the only bound is at
  the end, in `fold`: folding the stack reads v's digits from the top, as
  `tree(digits(...))` does.
- A Shape has no labels, so swapping a merge's two children (both complete
  trees of one size) keeps the shape. `stream.order` closes that: the
  segments, read bottom to top, stay in order through every merge and the
  final fold (an append argument, no bound). Shape and in-order leaves
  determine the tree. Erasure lemmas (`pop2.shape`, `lazy.shape`,
  `fin.shape`, `go.shape`) carry `stream.shape` from Shapes to Trees.

## Results

`bend/prove.sh`: ALL PROOFS CHECK, 28 laws and 45 lemmas, 229 s on the M5
Pro under outside load (ADR 0007: 224-244 s for 20). Without the known
answers the whole file checks in ~36 s.

Rust's own evidence for the same parts, from the official crate's
`src/test.rs`: each SIMD `compress` against the portable one on one
61-byte block; `hash_many` on 31 chunks at three counters; 39 lengths up
to 100 KiB against the reference implementation; 10,000 seeded random
inputs up to 4 KiB. No proofs, and the Rust compiler cannot state these
claims.

## What is not proven

(ADR 0015 adds the CPU, GPU and keyed trees for every input and ties the
tree laws to the code; the points below stand.)


- As in ADR 0007, the laws pass `~share` (Array.clone); the code passes
  `~fork` (Array.fork, `@unsafe`).
- b3io.bend imports hash.bend (Array.fork), so its stack is modelled, not
  imported; the model ignores the ROOT flag on the last merge and uses Nat
  where b3io uses U32 (`n >> 1`, `n & 1`).
- `tree.parents` says the group tree has g - 1 parents; that `tree8o`
  records exactly those (its `ku >= 5` rule) is checked against bao-tree
  by `bench/iroh`'s `ob_check`, not by a law.
